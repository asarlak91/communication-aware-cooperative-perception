# Communication-Aware Cooperative Perception

A clean Python reimplementation of the core methodology and selected experiments from:

**Extended visibility of autonomous vehicles via optimized cooperative perception under imperfect communication**  
Transportation Research Part C 180 (2025) 105350  
DOI: https://doi.org/10.1016/j.trc.2025.105350

The repository connects 2 parts of the paper in one modular pipeline:

1. **Helper selection** from vehicle location, visual range, and motion blur.
2. **YOLOv8 late fusion** using detections from successfully received helper transmissions.

> **Reimplementation note.** This is a reconstructed Python implementation for reproducibility and demonstration. It is not the historical MATLAB/CARLA and Communication and resource allocation codebase used to generate every result in the publication.

## Method

### Stage 1: Helper selection

For each candidate helper, the code evaluates:

- `f1`: location/distance cost over the CP horizon,
- `f2`: inverse collective effective visual range,
- `f3`: motion-blur cost.

The composite objective is represented as a fractional program and solved with a Dinkelbach outer loop. Two subproblem solvers are provided:

- `exact`: exact enumeration of the binary Dinkelbach subproblem for small `N` (recommended for the paper-scale `N=10` experiments and for validation),
- `sdp`: a lifted semidefinite relaxation of the nonconvex binary QCQP, followed by deterministic rounding and one-swap local improvement. This option requires `cvxpy` and an SDP-capable solver.


### Stage 2: Perception and late fusion

When images are supplied, the pipeline runs actual Ultralytics YOLOv8 inference independently on the ego image and helper images. Detections from failed helper transmissions are removed, and surviving detections are combined with class-wise IoU/NMS late fusion.

The late-fusion implementation assumes helper detections are expressed in a common reference/image coordinate system or have already been aligned.

## Installation

```bash
pip install -r requirements.txt
```

## Quick start: optimization

This path does not require images or YOLO weights:

```bash
python run_pipeline.py --N 10 --M 3 --helper-solver exact
```

The output includes selected helpers, packet-success probabilities, integer RB allocation, transmit powers, throughput, and energy.

For the SDP-relaxed helper-selection path:

```bash
python run_pipeline.py --N 10 --M 3 --helper-solver sdp
```

## Optional YOLOv8 end-to-end demo

Provide one ego image and exactly `N` helper images in candidate order:

```bash
python run_pipeline.py \
  --N 3 --M 1 \
  --ego-image sample_data/ego.jpg \
  --helper-images sample_data/helper1.jpg sample_data/helper2.jpg sample_data/helper3.jpg \
  --yolo-model yolov8n.pt
```

The first Ultralytics run may download model weights if they are not already present locally.

## Tests

```bash
python -m pytest -q
```

The tests verify that:

- exact Dinkelbach helper selection matches direct exhaustive minimization,
- packet success remains a valid probability,
- resource allocation satisfies the total RB and power constraints.

## Scope

This repository intentionally does **not** include the original 2,000+ image CARLA dataset or the complete historical MATLAB experiment environment. The goal is a compact, readable implementation of the paper's central optimization, communication, and cooperative-perception pipeline.
